# Decisions Log

Judgment calls made during the autonomous build, per the spec's Autonomous Execution rules.

- **Scaffold merge**: the repo root was not empty (README, `docs/specs.md`), and `@arcgis/create` only scaffolds into a new directory — scaffolded into a temp dir and merged into the root, keeping `docs/`.
- **Removed `@arcgis/charts-components`**: the template ships it, but this app has no charts; removing it also resolved the only `npm audit` findings (moderate, in its transitive `ajv`).
- **Git author**: per the owner's choice, repo-local git config uses `sascha.brunner@gmail.com` (personal address for the public repo) instead of the globally configured work address.
- **Vite `base` is always `/computer-graphics-explorer/`**: also in dev, so base-path bugs (assets, lazy chunks, worker URLs) surface immediately instead of only on Pages. Hash routing makes deep links work regardless.
- **Tailwind 4 (CSS-first)**: used the current Tailwind major with `@tailwindcss/vite`; dark mode is driven by a custom variant bound to Calcite's `calcite-mode-dark` class so one toggle controls both systems.
- **Term data split per category**: instead of one giant `terms.ts`, one file per category under `src/data/terms/` — smaller diffs for contributors adding a term; all files are merged and zod-validated in `src/data/index.ts`.
- **Several terms share one playground**: e.g. `shadow-mapping` and `soft-vs-hard-shadows` both point at the `shadows` demo. Cheaper than near-duplicate demos, and the shared frame keeps context.
- **Keyless-first ArcGIS demos**: scenes use basemap `osm`, `world-elevation` ground, and the public OSM 3D Buildings SceneServer (all verified token-free), so every demo works without an API key; a key only upgrades basemap options. This satisfies "degrade gracefully" without a degraded mode.
- **No-network rule for Three.js assets**: drei's `<Environment>` presets fetch HDRs from a CDN, which the spec forbids — PBR demos use `RoomEnvironment` via `PMREMGenerator` (bundled with three), and textures are generated procedurally on offscreen canvases.
- **Anti-aliasing demo scope**: MSAA is toggled by remounting the Canvas with a different context `antialias` flag, and supersampling via the `dpr` prop; FXAA/TAA are explained in the caption rather than adding a postprocessing dependency.
- **SSAO in ArcGIS SDK v5**: `ambientOcclusionEnabled` was removed in v5 (AO is automatic via adaptive rendering), so the ambient-occlusion demo can't offer a real on/off switch through the public API — the demo explains this honestly instead of faking a toggle.
- **Search palette is hand-rolled** (div overlay + input + listbox) instead of `calcite-dialog`: full control over command-palette keyboard behavior (arrows/enter/escape) without fighting web-component focus internals.
- **MSAA/AA captions, GI demo "fakes" labeled**: real-time GI in the Cornell box is approximated with placed fill lights and the caption says so — honesty over fake physics.
- **StrictMode WebGL gotcha**: demos avoid `loseContext()` in React cleanup because StrictMode remounts reuse the same canvas, which would permanently kill the second mount's context.
- **LOD demo controls kept honest**: `SceneView.qualityProfile` is runtime-settable in v5 and shipped as a real control; `LayerView.suspended` turned out to be read-only, so the planned "suspend streaming" toggle was dropped rather than faked.
- **Guided tour built** (nice-to-have): everything else was done and verified, so "Rendering Pipeline 101" shipped — 11 ordered stops reusing the term articles via a shared `TermArticle` component, with per-step connective blurbs and a clickable progress bar.
- **One committed binary asset**: the glTF-PBR demo bundles the Khronos sample "WaterBottle" (CC0-1.0), textures downscaled at build time from 9 MB to 632 kB — bundled assets honor the no-runtime-network rule.
- **Terrain exaggeration via `BaseElevationLayer` subclass**: v5's `Ground` has no exaggeration property, so the demo wraps the Terrain3D service and scales fetched tile values (the documented Esri pattern); `ElevationTileData.values` is readonly in v5, so a new scaled array is returned rather than mutated.
- **Honest performance counters**: the instancing demo reads real `gl.info.render.calls` (frustum culling makes "one mesh each" report ~1830, not 2000 — kept, it's the truth); the backface demo implements "no culling" as a genuine second back-face pass so the triangle counter honestly doubles (`DoubleSide` wouldn't change what `gl.info` counts).
- **Scene streaming uses Esri's public Girona integrated mesh** (the Frankfurt sample is dead); streaming stats surface `view.performanceInfo` memory numbers with an "experimental API" note in the UI.
- **Phase 5 introduced `<arcgis-map>` (2D) as a fourth renderer flavor** — only where 2D has an honest lever 3D lacks: `layer.effect` bloom (2D-only per typings), `ImageryTileLayer.interpolation`, RasterStretchRenderer min/max/gamma, vector-vs-raster tiles. Rejected for no honest lever: draw-call counters, atlas internals, AA toggles, featureEffect-blur-as-DoF.
- **`<arcgis-map>` gotcha**: the element never creates its view without a basemap/map supplied up front (no ready event fires) — basemaps are passed as constructed instances, never set later, and never shared between two views.
- **Imagery demos run on Terrain3D's raw F32 LERC tiles**: client-side resampling makes interpolation flips instant and the stretch genuinely remaps >8-bit data — the only verified keyless raw-pixel source (sampleserver imagery caches are pre-rendered 8-bit).
- **Phase 6 Mesh API strict typings**: v5 `vertexAttributes` require typed arrays with an explicit `<ArrayBuffer>` generic (`Float64Array<ArrayBuffer>` positions, `Float32Array<ArrayBuffer>` normals/uv) — the SDK doc examples show plain `number[]`, which strict TS rejects; helper functions must annotate the generic or inference falls back to `ArrayBufferLike` and fails.
- **Flat vs smooth normals via de-indexed vertices**: the scene-mesh dome always uses unshared per-triangle vertices with `shading: "source"`, so hand-computed normal arrays are respected verbatim and both modes (and the winding flip) are pure in-place array edits + `vertexAttributesChanged()` — no Graphic rebuild.
- **Winding flip is the honest backface toggle**: SDK meshes render single-sided, so reversing each triangle's index order genuinely culls the dome from outside — no faked visibility switch.
- **UV origin taught, not hidden**: the engine samples textures in the glTF/image convention (v = 0 at the top). The first scene-uv build assumed GL's v-up and rendered the test card mirrored — instead of silently flipping the canvas, the demo adopts the image convention end-to-end (base UVs, (0,0) arrow, grid labels) and the caption teaches the classic V-flip gotcha.
- **MeshTexture wraps by default**: `wrap: "repeat"` is the default, so the UV tiling lesson needs no extra config; canvas-backed textures update reliably by assigning a fresh `MeshTexture` and re-adding the Graphic.
- **Transparent ghost needs `alphaMode: "blend"`**: the default `"auto"` masks alpha < 0.5 to fully invisible — the mesh-transform "model space" ghost box only works as a real blend.
- **RealisticTrees web style verified keyless**: style item + ~3.5 MB glTF resource on static.arcgis.com return 200 token-free; one `fetchSymbol()` result (PointSymbol3D) is reused across all graphics so the engine can instance the mesh. No draw-call count is claimed anywhere — the demo measures its own rAF frame times instead.
- **`Mesh.offset()` on local-vertex-space meshes moves the origin in spatial-reference units**: horizontal offsets are DEGREES on a WGS84 scene (z stays metric). Found in live verification when the z-fight demo's blue slab landed 20° east (Ukraine) — and the same latent bug sat in phase 6's mesh-transform east slider (unseen because its default was 0). Both now convert metres → degrees via metres-per-degree at the site's latitude.
- **Water reflections include real scene geometry** (qualityProfile "high"), verified even under headless SwiftShader — so the water-ssr demo's vanish-at-frame-edge lesson works everywhere the site runs.
- **Co-planar client meshes genuinely z-fight**: the engine applies no internal bias to two `createPlane` meshes at identical absolute z — the scene-zfight premise verified live (red/blue pixels interleave and dance with the camera).
- **Geodesic path pinned at 200 km display altitude**: at z = 0 every coarse chord is buried inside the planet and the tessellation lesson is invisible; at 200 km the 5,000 km chords still plunge through the Atlantic while the densified arc reads cleanly. `geodeticDensifyOperator` interpolates z linearly, so vertices are re-pinned after densify.
- **The OSM vector basemap's sprite atlas is fully public**: sprite.json (871 entries) + sprite.png on basemaps.arcgis.com serve keyless with `Access-Control-Allow-Origin: *`, so the sprite-atlas demo draws the production atlas into its own canvas.
- **RenderNode stretch shipped — and verified under SwiftShader**: the posterize pass compiles, runs and toggles cleanly even on software WebGL, so the shader/frame-buffer/render-pipeline companion works everywhere the site does. The demo degrades honestly (pass-through + caption) if compilation ever fails.
- **Decorators break Vite's react plugin**: `@subclass` parses in tsc (experimentalDecorators) but @vitejs/plugin-react's Babel pass has no decorator syntax plugin — the SDK's `RenderNode.createSubclass({...})` path is used instead, with a typed constructor cast (`FBOTexture` is deliberately an empty interface in the typings; the official samples read `.glName`, narrowed locally).
- **State safety over speed in the render node**: the pass calls `resetWebGLState()` after drawing instead of tracking touched state — conservative, documented by Esri as the safe option, and irrelevant to perf for a teaching demo.
- **Phase 8 shipped same-day, zero code fixes needed**: all four demos passed driven live verification (capture button, aperture crank, band switch) on the first run — the phase-6/7 gotcha list embedded in the build prompts paid for itself.
- **Toronto bands are BGR+NIR, not RGB**: bandNames = [Blue, Green, Red, NearInfrared], so natural color is bandIds [2,1,0] and color-infrared is [3,2,1]. The plan's illustrative [0,1,2] would have swapped red/blue — reading service metadata before building is mandatory, as the plan required.
- **No stretch slider on the false-color demo**: RasterStretchRenderer is a single-band operator and would collapse the three-band composites; the 11-bit→8-bit display-mapping lesson lives in the caption instead. Export format png32 keeps band math lossless.
- **NIR-only mode uses bandIds [3,3,3]** (same band on all three channels) rather than [3], guaranteeing a grayscale composite instead of a server-side single-band colormap default.
- **FXAA is dropped during the AA capture** and restored after, so the three-resolution comparison shows pure resolution effects; the demo's FXAA is labeled as a second, deliberately visible pass on top of the engine's own AA.
- **Accumulation motion blur labeled honestly**: exponential frame-history blend (long-exposure style), explicitly distinguished in captions from per-pixel velocity-buffer motion blur used by modern games.
- **Phase 9's critical discovery — `opaque-color` injections get erased**: the material-lab node faithfully replicated the official windmills sample (slot, matrices, local-origin technique) yet the sphere never reached the screen. Framebuffer readback proved the pixels WERE written (`glError 0`, shaded crimson in the buffer) and then replaced downstream — the engine resolves its real (multisampled) opaque buffer over custom modifications in this SDK version. Fix: inject geometry at `composite-color` (the slot every shipped fullscreen pass already uses); depth testing against the scene still works there. Documented in SceneMaterialLab.tsx for future render nodes.
- **`bindRenderTarget()` does not reset the viewport** — set it from `camera.viewport` before drawing custom geometry (a prior internal pass may have left it elsewhere).
- **Render-coordinate frame verified stable**: hybrid-ray computes sphere render coords once; a camera away-and-back round trip reproduces pixel-identical placement, and the path tracer's spheres track navigation exactly (eye-relative float64→float32 per frame). No per-frame re-projection needed.
- **Path tracer self-drives to a 512-SPP cap** via requestRender-inside-render (the documented continuous pattern), resets on camera moves/resize/slider changes (1 SPP fresh noise — verified live), and exposes an honest "show single sample" view of the raw estimator.
- **IBL stretch mode NOT shipped** (per the plan's degrade-to-not-shipping rule): material-lab consumed its headroom on the opaque-color investigation. IBL stays parked; the r3f demo covers the term's teaching.
- **Smoke test updated for companion demos**: term pages can host multiple canvases now; the r3f assertion uses `.first()` instead of assuming a single canvas.
- **Phase 10 verification catches**: painters-order's shape offsets were authored in raw degrees instead of kilometres (the shapes rendered 200 km off-screen — radii were converted, centres weren't); fixed with the same metres-per-degree helpers. ExtentCulling needed a null guard (`view.extent` is null before first layout).
- **Vite dev module realms can break SDK type checks**: constructing a fresh `RasterShadedReliefRenderer` for assignment triggered "Assigning an instance of X which is not a subclass of X" — two copies of the class existed across dev chunks. Fix: clone the layer's CURRENT renderer and mutate the clone; the clone stays in the accepted realm and assignment still redraws. Applies to any renderer-swap demo that lazy-loads its renderer class.
- **Term pages as term-page composition grows, error triage must be per-figure**: the driven verifier initially attributed sibling scene demos' transient tile-fetch errors to the map demos under test (depth-buffer hosts three demos now).
- **The global API key broke the deployed site while dev stayed green**: `esriConfig.apiKey` attaches the key to every \*.arcgis.com request, and the basemaps-only key gets REJECTED (400 / invalid token) by public endpoints that serve anonymous requests fine. Live-site casualties found by the full 43-demo audit: tree-instancing (portal style resolution), scene-streaming + baked-lighting (Girona SceneServer refused to load), map-bloom (dark-gray vector basemap refused → blank map), plus harmless-but-noisy 400s on every OSM-buildings page (the companion FeatureServer metadata probe). Fix: `esriConfig.apiKeys.basemapStyles = key` — scoped to the one service the key is licensed for. Lesson: keyless dev builds cannot catch key-scoping bugs; audits must run against a key-carrying build.
- **Web-style symbols without the portal**: tree-instancing now fetches the style's `gltf`-flavor symbol JSON straight from static.arcgis.com (token-less CDN) into `PointSymbol3D.fromJSON` — the `web` flavor's resource wraps a JSON model format only the WebStyleSymbol path can resolve (renders as dots); the `gltf` flavor's resource.href is a plain .glb the engine loads directly.
- **edge-rendering is healthy but SwiftShader-heavy**: contour extraction over the whole buildings layer starves a software-GL tab (screenshots need 120 s timeouts); real GPUs are fine. Audit false-positive, documented so future sweeps use long timeouts there.
- **Double buffering got a true display simulator** (user feedback: "I would have expected to actually see half-drawn frames"): a ~30× slow-motion scanout beam reads the front buffer row by row while a simulated GPU paints the scene element by element — single buffering shows genuine half-drawn frames assembling on screen, immediate swap shows a wandering tear line, vsync shows the 60→30 snap. Simulation is the only honest route: the OS compositor always double-buffers a real canvas (the same reason the coverage report lists no ArcGIS companion for this term), and the caption says so.
- **The path-tracing companion now demonstrates architectural visualization, not a sphere exercise**: three fixed-seed red, warm-white, and teal pavilions sit close together so direct shadows and indirect colour transfer answer a credible external-renderer question. Their stacked-convex forms are independently authored; the CC BY-NC-SA Shadertoy building study is visual inspiration only, with no shader code copied into this MIT project.
- **Path-traced architecture stays in a float64 local ENU frame**: `renderCoordinateTransformAt()` anchors east/north/up at a foundation top resolved from the scene anchor plus four terrain corners. The fragment shader intersects at most ten exact convex solids (eight planes each), reads the engine's real sun direction/diffuse/ambient values, and resets its running mean when Daylight, camera, viewport, bounce count, or sample mode changes. A runtime astronomical check established that SDK 5.0.19's exposed direction is already surface-to-sun despite its legacy "incident" wording — negating it sends shadow rays below the horizon. ArcGIS still rasterizes terrain and the existing surroundings; shared depth lets them occlude the proposal but does not make them part of secondary light transport.
- **CORRECTED — a retained accumulation FBO does not need an extra `retain()`**: `acquireOutputFramebuffer()` already gives the custom node one ownership reference. The old path tracer retained every new history buffer and released only one reference, leaking a full-resolution FBO per sample. The rework stores the acquisition reference directly, releases the replaced buffer, attaches the input's wrapped `ManagedDepthAttachment` without testing it for a nonexistent direct `glName`, preserves emissive attachment 1, and deletes raw WebGL programs/VAOs in the subclass destroy hook.
- **A counterclockwise "exterior" ring renders as the world-sized inverse**: the water-fresnel polygon's original CCW ring is a _hole_ by Esri's winding convention, and the SceneView renders a hole-only polygon as everything EXCEPT the rectangle — the user saw water floating over Lake Thun near Interlaken and none over Lake Brienz. Verified live by red-filling both windings: CW fills the rectangle, CCW fills the rest of the world (with a z-fighting fringe at the boundary). Also verified: `new Polygon({ rings })` DOES infer `hasZ` from 3-element vertices (while `Polygon.fromJSON` does not), and under headless SwiftShader the realistic water symbol never draws at all — footprint debugging needs a plain fill symbol swapped in.
